# Resumable Jobs: pause, abort, continue

The one thing a long unattended Job could not do is park without losing work-in-progress. Considered: rail-verified unit writes (rejected — the rail books, it never judges content; a resumed agent's own transcript already knows what it wrote, and unit quality is the grade hook's job); keeping panes warm across a pause (rejected — a pane is a cheap terminal, the host session is the state, and a booked session pointer outlives any pane); keeping `relaunch` as a separate crash-recovery verb (rejected — three resume paths, each half right). Adopted: a Job is **resumable** — `pause` (SIGTERM) drains to the workflow's boundary (fan-out: the in-flight unit settles, no new claims; Coworker: a member mid-turn ends its turn, pending mail is *not* drained, it waits) then books `paused`; `abort` parks immediately (SIGKILL, pointers kept) and books `aborted`; an unbooked death is swept `orphaned` as ever — and all three park states `continue` identically: retire stragglers, respawn each pane of unfinished work with its host session resumed, prompt it "continue", restart the orchestrator, which rebuilds its flights from the pane ledger. The write-ahead ledger is the pane ledger, already born booked — the one addition is the host session id in the pane's transcript pointer, booked at spawn, *before* work starts, so even a SIGKILLed orchestrator leaves a resumable Job. The settle projection stays the single booking point (`done <id>` → `state.json`), drain is bounded by a configurable ceiling (`drain_timeout_ms` in workflow.toml, default the stall timeout; `AGENTIC_OS_DRAIN_MS` env; `pause --wait` writes a one-shot deadline; past it the straggler aborts, the wait never extends), and nothing auto-continues — a deliberate human verb, with a soft `continued ×N` counter replacing the hard relaunch cap. Default resume strategy is resume-session; `redo-unit` stays a per-workflow option (`resume = "redo-unit"`, archiving `units/<id>/.attempt-1/`). Milestones: M1 fan-out pause/continue; M2 Coworker (persist the relay delivery ledger as `relay.json` in the Job dir + one rail-generated nudge to a member interrupted mid-turn); M3 verb consolidation — `relaunch` absorbed into `continue`.

## Amendment (2026-10-13): refusals speak — the relay ledger carries why, and the nudges quote it

The 2026-10-12 p10 wave-2 deaths: members wrote message files the relay refused (a trailing `}`, a topic for a filename, seq starting at 0), and the only record was a line in orchestrator.log — the member was never told, so it idled to death at the nudge cap "stalled", a wrong diagnosis the levy inherited. Adopted: a refusal carries its attributable sender (the payload's `from` when the JSON parsed, else the filename's sender slot — a stranger's name is filtered at use); `relay.json` gains an additive `refusedDetail` array (file, why, from) so a resumed run still knows; the nudge ladder quotes the member's own refusals back at it with the fix spelled out; a nudge-cap death's reason and the ledger wake append the refused list; the report carries a `relay` row for unresolved refusals — and a stop with unresolved refused mail no longer reports `done`. A file that later parses good (or is deleted) heals out of the detail — the quote disappears once the sender acted on it.
