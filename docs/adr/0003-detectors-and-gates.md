# The program owns the photograph's source. The OS owns tick.

skill-rsi's world — `protocol.json` waves, `log.txt` done-lines — was hardcoded in the watcher. A program whose wave is "PRs merged" could not say so. Considered: program-supplied tick (Airflow-provider style). Rejected — that is a second scheduler per program; the rail could no longer promise one reopen rule, one retry cap, one receipt shape, and a dead orchestrator could not be relaunched into a loop it does not own. Airflow itself never lets a DAG ship a scheduler; its sensors are the pluggable part. Adopted: `[detectors]` (`signal`, `end`) and `[gates]` commands in `workflow.toml`, plus a `gate` step verb — the program names where the photograph comes from, `tick` and the rail stay OS code. Liveness stays rail-owned: a dead pane is dead even under a custom end detector.
